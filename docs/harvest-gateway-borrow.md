# 网关借票

入口：智能运维 → 打票流程（`/admin/harvest-flow`）→ 网关借票。默认关闭，卡片默认折叠。来源与目标必须分开选择；保存启用后自动获取路由并验证目标。来源门票与 Cookie 只留在当前实例内存，不返回管理接口、不写历史表。

来源请求完整成功后，同时取得 `x-codex-turn-state`、`__oailb` 及有效的 `__cflb`。目标使用自己的 OAuth 凭据，在同一出口上连续两次携带相同来源票和 Cookie；两次 HTTP 200 且响应流完整结束即通过，正式请求继续使用这张来源票。上游返回新票只记录为 `target_probe_ticket_rotated`，不拒绝、不替换来源票、不续期；无新票也可通过。来源缺票、请求或流失败、路由改变仍不可用。手动验证重新探测，连通性通过不证明上游采用了来源票，也不证明实际模型身份或智力。账号页独立的旧版门票状态测试判据不变。

支持来源代理亲和、托管 Mihomo 节点轮换及失败冷却。Astra 使用独立回环端口 17925–17932，与普通打票和 BPS 隔离。来源票默认从首次获取起最多使用 240 秒；管理员可设更短的 30–240 秒上限。可解析的票据签发时间、Cookie 更早的到期时间会进一步缩短窗口。探测、正式请求、返回新票及重复取得同一来源票都不延长原期限；过期后重新获取和验证。票体、路由 Cookie 或出口变化时重新验证，不能沿用旧缓存。无可用路由时拒绝目标借用，不自动退回未验证出口。

可选 WS 固定会话按 API Key、分组、账号和客户端会话隔离；后续请求必须提供响应 ID 并继续使用原连接。新建 WS 连接在最终握手前重新应用并检查来源票与 Cookie，已建立连接仍按原 WS 会话期限管理。借票只共享门票和路由 Cookie，不复制来源账号的 OAuth 凭据或会话认证 Cookie。选定的 Astra 目标由借票链路负责票据准入，不再强制要求目标有自己的普通打票库存；其他账号和模型仍使用原打票策略。

可选号池调度在目标探针通过且路由有效时恢复本功能拥有的变更；否则按设置暂停账号、屏蔽 Astra 模型或移出指定分组。只修改所选目标，切换模式先恢复旧动作，遇到人工编辑冲突不覆盖。关闭接管保留当时状态。仅切换调度设置不清空已验证路由。

新增 `astra_gateway_history` 和 `astra_scheduling_states` 两张表；保留原私有版本迁移文件名和内容，已有实例可兼容。历史通过不代表当前可用。启用后会发送来源获取和目标探针请求；页面读取状态不触发请求。
